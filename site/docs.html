स्वरSwar API · v1
Reference

Send text. Get a voice back.

One POST, one key, audio in the response body. Hindi and English, in a voice you pick by name.

Preview. This runs on a single machine that generates one request at a time. Expect a queue under load, and do not build anything time-critical on it yet. We would rather you knew that before you integrated than after.

Authentication

Every request carries a key in an Authorization header. Ask us for one — there is no self-serve signup yet.

Authorization: Bearer swar_live_a1b2c3d4_...

Keys are shown once when created and stored only as a hash, so we cannot resend one. If a key leaks, tell us and we will revoke it and issue another. Keep it server-side: anything in a browser or a mobile binary is public.

Generate speech

POST /v1/speech — returns the audio bytes directly, not a URL. There is no object store behind this, and a link that expires is a worse contract than bytes that do not.

# Hindi, in atul's voice, as MP3
curl -X POST https://your-tunnel.trycloudflare.com/v1/speech \
  -H "Authorization: Bearer $SWAR_KEY" \
  -H "Content-Type: application/json" \
  -d '{"text":"नमस्ते, यह API से आई हुई आवाज़ है।","voice":"atul"}' \
  --output hello.mp3
# Python
import requests

audio = requests.post(
    "https://your-tunnel.trycloudflare.com/v1/speech",
    headers={"Authorization": f"Bearer {KEY}"},
    json={"text": "आपका काम हो गया है।", "voice": "saurabh"},
    timeout=120,
).content
open("out.mp3", "wb").write(audio)

Body

Field
textRequired. Hindi, English, or both. Up to 3,000 characters — roughly four minutes of speech.
voiceRequired. A name from /v1/voices, e.g. "atul". Case-insensitive.
formatmp3 (default), wav, flac, opus.

Response headers

Header
X-Audio-SecondsLength of the audio returned.
X-Billable-CharactersWhat this request counted as. Measured on your text, before our normalisation.
X-Queued-SecondsHow long it waited behind other requests.
X-Realtime-FactorSynthesis time ÷ audio length. Under 1.0 means faster than real time.
X-Language-WarningPresent only when your text is a language we render but do not support — today that means Nepali, which shares Hindi's script and comes out understandable but with Hindi phonology. Absent on every ordinary request. Worth logging. (Marathi is refused outright rather than warned about; see below.)

Check your usage

GET /v1/usage — the same numbers an invoice would be built from. billable_characters counts successful generations only; failures and rejections are reported beside it, never folded in.

{
  "billable_characters": 12480,
  "audio_seconds": 831.4,
  "generations": 96,
  "failed": 0,
  "rejected": 2
}

Plans and credits

GET /v1/plans needs no key — it is the pricing page as data, so a client can show an upgrade prompt without hardcoding what we charge. Credits are counted in characters, the unit this market quotes, and money is in rupees.

{"currency": "INR",
 "plans": [{"name": "creator", "inr_per_month": 499.0,
            "characters_per_month": 500000, "blocks_when_empty": false}],
 "overage_inr_per_10k_characters": 25.0,
 "payments_enabled": false}

GET /v1/balance is what your key has left.

{"plan": "free", "characters_remaining": 4200,
 "machine_seconds_remaining": 168.0, "overage_inr": 0.0}

machine_seconds_remaining is the honest unit and worth reading before a batch job. We synthesize at roughly 40 seconds of machine time per 1,000 characters, one generation at a time — so a million characters is about eleven hours of a machine that has twenty-four, not an instant. Sizing a job against this number beats discovering it from the queue.

Free accounts stop when the allowance is gone (402). Paid plans do not: they run into metered overage instead, because a narration that halts halfway costs you more than the overage does.

Payments are not live yet. payments_enabled is false and POST /v1/checkout answers 503 until we finish provisioning Razorpay. The ledger, the allowances and the 402 are all real and running today — only taking your money is not. Ask us and we will grant credits directly.

Errors

Every error is JSON with a stable code. Match on the code, not the message — messages get clearer over time, codes do not change.

{"detail": {"error": {"code": "unknown_voice",
                     "message": "No voice called 'priya'.",
                     "available": ["atul", "saurabh"]}}}
CodeStatus
missing_key401No Authorization header, or not a Bearer token.
invalid_key401Unknown or revoked. We cannot tell you which — that would be an oracle.
unknown_voice404Carries available, so you can see the real names.
ambiguous_voice409Two voices share that name. We refuse rather than guess — answering in the wrong person's voice is not a risk we take.
text_too_long413Over 3,000 characters. Split it into sections.
rate_limited429Too many requests for this key. Wait and retry.
unsupported_format400Carries the list we do support.
insufficient_credits402Free plan, allowance spent. Carries characters_remaining and characters_requested. Checked before we synthesize, so you are not charged and not made to wait.
payments_unavailable503Razorpay is not configured yet. Not your integration.
unknown_plan400Carries the list of plan names.
unsupported_language400Carries language. Today: Marathi. Raised before synthesis, so you are not billed and not made to wait.

When the queue is full

A 503 with a Retry-After header in seconds. It means the machine is busy, not broken. Retrying immediately makes it slower rather than sooner — honour the header.

What this does not do yet

  • Streaming. You get the whole file when it is finished. A four-minute request takes minutes.
  • Indic languages beyond Hindi. Other scripts return an error rather than being spoken badly. Marathi is refused too (400 unsupported_language): it shares Hindi's script, so it would otherwise synthesize, but the engine cannot produce ळ at all and substitutes Hindi words for Marathi ones — audio that is confidently not Marathi, which we would rather not sell you. Nepali is served with an X-Language-Warning: it comes out understandable but in Hindi phonology.
  • Voice cloning over the API. Enrolment is done by us, with a recorded consent statement from the speaker.
  • An SLA. One machine, one person. Do not put it on a critical path.
Naturalness we have not measured — our own scorer is blind to prosody, and we would rather say so than estimate. On intelligibility we land inside the band of the major cloud systems on held-out sentences from a benchmark rated by 1,900 native speakers.
